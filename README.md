# Локальное зеркало Флибусты (Docker + OPDS)

Полнофункциональный веб-сервер, веб-читалка и OPDS-каталог для локальной копии Флибусты в Docker. Позволяет развернуть личную библиотеку на домашнем сервере, ПК или NAS (Synology, TrueNAS, OpenMediaVault, Unraid) с полным поиском, каталогизацией и возможностью чтения прямо в браузере или через сторонние читалки.

## Возможности

* **Чтение в браузере**: встроенный ридер для форматов `fb2`, `epub`, `mobi`, `pdf`, `docx`, `rtf`, `txt`, `html`. Для формата `fb2` запоминается позиция чтения.
* **OPDS-каталог (`/opds/`)**: полная поддержка читалок для телефонов, планшетов и электронных книг (FBReader, Moon+ Reader, KOReader, PocketBook и др.).
* **Личные книжные полки**: возможность создавать полки избранных книг, авторов и серий (с привязкой по UUID).
* **Мощный поиск**: полнотекстовый триграммный поиск PostgreSQL по названиям, авторам, сериям и аннотациям.
* **Гибкость хранения**: архивы книг можно хранить на любом диске, сетевом ресурсе или внешнем массиве.

---

## Архитектура и стек

* **Веб-сервер**: Nginx (Alpine) — отдача статики и проксирование запросов к PHP-FPM.
* **Бэкенд**: PHP 8.1 FPM (Alpine) с модулями `pdo_pgsql`, `gd`, `zip`, `bz2`.
* **База данных**: PostgreSQL 16 с расширениями `pg_trgm` (триграммный индекс для быстрого поиска) и `uuid-ossp`.
* **Автоматические конвертеры**: встроенный конвейер импорта и адаптации официальных MySQL-дампов Флибусты в формат PostgreSQL.

## Быстрый запуск из Git

### Вариант 1: Автоматическая установка в одну команду (рекомендуется)

Скрипт сам проверит Docker, спросит путь к книгам, настроит конфигурацию и запустит контейнеры:

**Для Linux / NAS / macOS (по SSH):**
```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/scanek/flibusta/main/install.sh)"
```

**Для Windows (PowerShell с Docker Desktop):**
```powershell
irm https://raw.githubusercontent.com/scanek/flibusta/main/install.ps1 | iex
```

---

### Вариант 2: Ручная установка

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/scanek/flibusta.git
   cd flibusta
   ```

2. Скопируйте файл конфигурации:
   ```bash
   cp .env.example .env
   ```

3. Настройте файл `.env` (укажите ваш путь к папке с книгами в `BOOKS_DIR`):
   ```env
   BOOKS_DIR=/путь/к/вашим/книгам
   WEB_PORT=27100
   ```

4. Соберите и запустите контейнеры:
   ```bash
   docker compose build
   docker compose up -d
   ```

После старта портал доступен:
* Веб-интерфейс: `http://<IP-сервера>:27100/`
* OPDS-каталог: `http://<IP-сервера>:27100/opds/`

## Настройка окружения (`.env`)

Все параметры централизованно задаются в файле `.env`:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOOKS_DIR` | `./Flibusta.Net` | **Самый важный параметр.** Путь к папке с архивами книг (`*.zip`) на хосте. Можно указать любой путь: внешний диск, NAS-папку (`/srv/dev-disk-.../books` или `D:/Books/flibusta`). |
| `WEB_PORT` | `27100` | Внешний HTTP-порт веб-интерфейса и OPDS. |
| `PG_PORT` | `27101` | Внешний порт PostgreSQL (для прямого доступа к базе при необходимости). |
| `POSTGRES_USER` | `flibusta` | Имя пользователя базы данных. |
| `POSTGRES_PASSWORD` | `flibusta` | Пароль к базе данных PostgreSQL. |
| `POSTGRES_DB` | `flibusta` | Название базы данных. |
| `SERVICE_PASSWORD` | *(пусто)* | Пароль HTTP Basic Auth для защиты раздела «Сервис» (`/service/`). Если не задан — раздел доступен без пароля. |
| `SQL_DIR` | `./FlibustaSQL` | Папка на хосте для дампов базы данных (`*.sql.gz`). |
| `CACHE_DIR` | `./cache` | Папка для распакованных обложек, фото авторов и временных файлов. |
| `FLIBUSTA_SQL_URL` | `https://flibusta.is/sql/` | Адрес зеркала для скачивания дампов таблиц. |
| `FLIBUSTA_DAILY_URL` | `https://flibusta.is/daily/` | Адрес зеркала для ежедневных обновлений архивов книг. |
| `AUTO_IMPORT_ON_START` | `false` | Если `true`, Docker при первом запуске сам скачает и импортирует дамп в PostgreSQL в фоне, если база пустая. |

## Первоначальное наполнение библиотеки

Библиотека состоит из трёх частей: **база данных**, **файлы книг** и **обложки**.

### 1. Скачивание и импорт базы данных (SQL) в Docker
Дампы содержат каталожную информацию (названия, авторы, жанры, аннотации, связи).
Процесс встроен прямо внутрь Docker-контейнера. Выберите любой удобный способ:

* **Способ А (полный автомат при старте):**
  Укажите в `.env`:
  ```env
  AUTO_IMPORT_ON_START=true
  ```
  При первом `docker compose up -d` контейнер обнаружит пустую базу и сам в фоне скачает все таблицы и заполнит PostgreSQL.

* **Способ Б (одной командой через Docker):**
  ```bash
  docker compose exec php-fpm /application/tools/docker_sync_sql.sh
  # или через отдельный профиль запуска:
  docker compose run --rm sync-sql
  ```

* **Способ В (из браузера):**
  Откройте в веб-интерфейсе раздел **«Сервис»** (`http://<IP>:27100/service/`) и нажмите **«Обновить базу»**. Контейнер сам в фоне скачает таблицы, конвертирует и импортирует их, отображая статус в веб-интерфейсе.

* **Способ Г (хостовый скрипт):**
  ```bash
  ./getsql.sh -d
  ```

### 2. Размещение архивов с книгами
Архивы книг имеют имена вида `f.fb2.000001-010000.zip`, `f.fb2.010001-020000.zip`, `f.n.000001-010000.zip` и т.д.
* Положите уже имеющиеся архивы в папку, указанную в `BOOKS_DIR`.
* Для докачки свежих ежедневных архивов запустите:
  ```bash
  ./update_daily.sh
  ```

### 3. Обложки и фотографии авторов
Для отображения картинок и обложек для форматов, отличных от FB2:
```bash
./getcovers.sh
```
*(Скрипт скачивает архивы `lib.a.attached.zip` и `lib.b.attached.zip` в каталог `cache/`).*

### 4. Первичная индексация архивов
После того как база загружена, а zip-файлы размещены в папке с книгами:
* Откройте веб-интерфейс `http://<IP-сервера>:27100/service/`.
* Нажмите кнопку **«Сканирование ZIP»** (или выполните `docker compose exec php-fpm php /application/tools/app_update_zip_list.php`). Это свяжет номера книг в базе с конкретными zip-архивами.

## Запуск долгих процессов в фоне

Скачивание сотен гигабайт книг и гигабайтных дампов может занимать часы. Чтобы SSH-сессия не прерывала процесс:

### Способ 1: Встроенный флаг `-d` (просто и надежно)
Скрипты умеют сами уходить в фон:
```bash
./getsql.sh -d
./update_daily.sh -d
./getcovers.sh -d
```
Скрипт напишет PID процесса и имя лог-файла. Терминал можно закрывать.

Смотреть за процессом в реальном времени:
```bash
tail -f getsql.log
# (Ctrl+C для выхода из просмотра; процесс продолжит работать)
```

### Способ 2: Через утилиту `tmux`
```bash
# 1. Создать сессию
tmux new -s flibusta

# 2. Запустить скрипт внутри сессии
./getsql.sh

# 3. Отключиться и оставить работать:
# Нажмите Ctrl+B, затем отпустите и нажмите клавишу D (Detach)

# 4. Вернуться в сессию в любое время:
tmux attach -t flibusta
```

### Способ 3: Через веб-интерфейс
В меню **«Сервис»** веб-портала по кнопке **«Обновить базу»** импорт запускается в фоне автоматически с выводом текущего этапа и индикатора прогресса.

## Нюансы и тонкости работы

### Права доступа к папкам (Linux / NAS)
Внутри Docker контейнер `php-fpm` работает под системным пользователем `www-data` (UID 82 в Alpine Linux).
Если хостовые папки созданы из-под `root`, веб-сервер внутри контейнера не сможет записывать кэш обложек или логи синхронизации (`sync.log`), выдавая `Permission denied`.

**Решение (разово на хосте):**
```bash
# Выдать полные права на запись для базы и кэша:
chmod -R 777 cache FlibustaSQL

# Или назначить владельцем системного пользователя контейнера (UID 82):
chown -R 82:82 cache FlibustaSQL
```

### Права на исполнение скриптов
Если скрипт пишет `cannot execute: required file not found` или `permission denied`:
1. Убедитесь, что у скриптов есть флаг исполнения:
   ```bash
   chmod +x *.sh application/tools/*
   ```
2. Если файлы редактировались в Windows, очистите окончания строк от `\r` (CRLF):
   ```bash
   sed -i 's/\r$//' *.sh application/tools/*.sh
   ```

### Скорость первого импорта базы
* Импорт полной базы Флибусты с нуля занимает от 15 до 40 минут в зависимости от скорости диска.
* Настоятельно рекомендуется, чтобы база PostgreSQL (`db-data`) и директория `FlibustaSQL` находились на **SSD/NVMe**, а не на медленном HDD. Сами книги (`BOOKS_DIR`) при этом отлично чувствуют себя на обычном HDD массиве.

## Регулярное автоматическое обновление

Дампы базы на серверах Флибусты обновляются регулярно, а новые книги выходят ежедневно. Чтобы ваша библиотека всегда оставалась актуальной, настройте автоматическое обновление.

### 1. Ежемесячное обновление через Linux Crontab (рекомендуется)
Процесс занимает 15–30 минут, поэтому его удобно ставить на ночное время (например, в **04:00 ночи 1-го числа каждого месяца**).

Откройте планировщик от пользователя `root`:
```bash
crontab -e
```

Добавьте одну из строк в конец файла (замените путь на ваш каталог с проектом):

* **Только обновление базы данных и каталога (SQL):**
  ```cron
  0 4 1 * * cd /полный/путь/к/flibusta && docker compose exec -T php-fpm /application/tools/docker_sync_sql.sh >> FlibustaSQL/cron.log 2>&1
  ```

* **Комплексное обновление (скачивание свежих книг за месяц + обновление базы):**
  ```cron
  0 4 1 * * cd /полный/путь/к/flibusta && ./update_daily.sh && docker compose exec -T php-fpm /application/tools/docker_sync_sql.sh >> FlibustaSQL/cron.log 2>&1
  ```

> **Важно:** Флаг `-T` в `docker compose exec -T` обязателен — он отключает псевдотерминал TTY, обеспечивая корректное выполнение в неинтерактивном режиме cron.

### 2. Настройка через веб-интерфейс OpenMediaVault (OMV)
Если ваш NAS работает под управлением OMV:
1. Откройте панель управления OMV.
2. Перейдите: **Система (System)** ➔ **Запланированные задачи (Scheduled Tasks)** ➔ **Создать (+)**.
3. Укажите параметры:
   * **Включено:** Да
   * **Время выполнения:** Выберите `Раз в месяц (Monthly)` (или укажите: день `1`, час `04`, минута `00`).
   * **Пользователь:** `root`
   * **Команда:**
     ```bash
     cd /полный/путь/к/flibusta && docker compose exec -T php-fpm /application/tools/docker_sync_sql.sh
     ```
4. Сохраните и примените настройки.

### 3. Просмотр отчёта автообновлений
Все результаты автоматических запусков cron сохраняются в файл лога:
```bash
cat /полный/путь/к/flibusta/FlibustaSQL/cron.log
```

## Настройка подключения в читалках (OPDS)

* **FBReader / Moon+ Reader / Librera / ReadEra**:
  1. Перейдите в раздел «Сетевые библиотеки» / «Каталоги OPDS» -> «Добавить каталог».
  2. Название: `Моя Флибуста`
  3. Адрес каталога: `http://<IP-вашего-сервера>:27100/opds/`
* **KOReader**:
  1. «Поиск и каталоги» -> «OPDS каталоги» -> «Добавить новый каталог».
  2. URL: `http://<IP-вашего-сервера>:27100/opds/`

## Обновление самого проекта из Git

Когда в репозитории выходят улучшения кода, обновите проект без потери ваших настроек:

```bash
cd /полный/путь/к/flibusta

# 1. Сохраняем локальные настройки (.env)
git stash

# 2. Подтягиваем свежий код
git pull origin main

# 3. Возвращаем локальные настройки
git stash pop

# 4. Обновляем права доступа
chmod +x application/tools/* *.sh
chmod -R 777 cache FlibustaSQL

# 5. Перезапускаем контейнеры
docker compose down
docker compose up -d
```
Все ваши настройки в `.env`, база данных PostgreSQL в томе `db-data` и скачанные архивы книг сохраняются.
